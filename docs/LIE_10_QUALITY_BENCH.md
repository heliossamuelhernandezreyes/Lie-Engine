# LIE-10: complex GLB, directional relighting, matched viewport benchmarks

## What is actually implemented

- Original Blender generator `tools/create_lie_complex_fixture_blender.py`: multi-material nontrivial assembly of radial armor, rings, cylinders, panels and details. >45 independent Blender mesh objects; >2500 triangles, deterministically generated and exported to glTF.
- LIE-10 keeps actual **albedo, 16-bit normal and linear depth** image source captures, created by the existing Blender triplet exporter; these images are not photorealistic PBR and are loaded into GPU buffers once.
- New Vulkan `lie10_pipeline.glsl` carries out directional **Lambert lighting on captured normals**, independent of angle-camera projection. Key lighting is switchable between warm and cool directions via small persistent GPU buffer updates. It does NOT simulate Godot point-light shadows, screen-space shadows, reflections, IBL, specular or GI.
- The identical complex GLB is imported as the *reference only*, with same viewpoint and source capture manifest center. Lie mode does not draw source geometry.
- CI uploads paired Godot screenshots for Lie GPU / original glTF at 0° and novel 35°, plus warm/cool lighting and a JSON report.
- CI records **silhouette IoU** and 30-frame p50/p95/p99 wall-clock frame spacing for raster and Lie. Rendering is done in the same viewport and same process but shader lighting/materials are not identical, and raster baseline does not include the extra Lie compute shader. These are first diagnostics, **not apples-to-apples matched shading** or a measured GPU speedup.

## Reproduction

This is a stacked experimental PR on LIE-09. The reference asset is generated by CI; no binary GLBs/PNGs are committed to Git. Run the Blender commands copied from the workflow to populate `gpu_compute/captures/complex_shard`, including `source.glb`. Open `gpu_compute/project.godot` using Godot 4.7.2 Forward+ / Vulkan and press Play; arrow left/right rotates, arrow up/down switches warm/cool directional light. CI runs `gpu_compute/test_lie10_diagnostics.gd`.

## Honest limitations

- Per-pixel normals and colors are subsampled to 128×128 for each of four horizontal viewpoints, despite 12 possible captured views. Fine thin geometry can vanish and silhouette IoU may be poor. Do not hide low numbers.
- Source colors / Blender material fallbacks use unlit base color, not standard Godot PBR. The source GLB reference uses Godot's native lighting. Thus silhouette IoU is more meaningful here than RGB/color PSNR.
- The GPU compute pipeline uses atomic writes and persistent buffers; the total number of samples remains fixed, irrespective of original triangle count. However that does not make it faster by itself.
- Software Vulkan CPU-driver data is **not hardware GPU latency**. Frame interval measures include engine scheduling, shader compilation warm-up and CPU wait. Actual Android testing needs identical device, resolution, render scale, thermal stabilization, GPU timestamp profiling and VRAM measurements.
- Camera movement and dynamic light alter data without source GLB in Lie mode, but normal maps are static. There is no pose animation or true physically based shading.
