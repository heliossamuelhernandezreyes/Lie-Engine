# Opaque material appearance and bounded raster work — WALL12 / 0.9

Base: `652d89e7fe99dc782c78aa5ad07a4ad7ab80d010` / WALL11.
This stage preserves the original 80-byte source bank, source selection,
seeded instance geometry, light field, collision shell and persistent visibility.
The shader is generated by `tools/lie_wall12_shader.py` from the accepted WALL11
kernel. Source-specific wall layout remains in the existing adapter.

## Less raster work with identical geometric acceptance

The old projection/raster loops inspect the square bounding each projected
ellipse, including pixels outside the viewport. `lie_splat_work.glslinc` solves
the ellipse's quadratic at each row and clips conservative pixel intervals to
the viewport and the original 8px-capped square. A one-pixel numerical guard
is included on each side. Original `covered()`, photographed support bounds,
tangent depth, depth tolerance, integer color/normal accumulation and source
ownership remain authoritative. There is no larger footprint, source deletion,
image blur or change to LOD quality. Rejected stage-3 projections no longer
fetch an entire source sample before checking visibility. Material values are
computed once per accepted sample rather than within every candidate-pixel loop.

Counters are optional and increment once per projection, after its local loop.
Shipping defaults disable both these counters and the existing per-light query
counters. They count candidate pixel tests, not shader instructions, bandwidth,
physical VRAM or FPS. Raw paired timestamps retain event serial and options.
Warm software Vulkan timings cannot establish speed on the Poco X7 Pro.

## Separate direct response for each light

`lie_opaque_brdf.glslinc` supplies an isotropic single-scatter GGX distribution,
height-correlated Smith visibility, Schlick dielectric Fresnel, and a Lambert
substrate attenuated by incident/outgoing Fresnel. The common kernel accepts
F0, substrate albedo, roughness, survival and independent light/view directions.
The adapter explicitly authors nonmetal F0=0.04 (IOR 1.5); it is not an optical
measurement from the photograph. Existing source roughness remains authoritative.

The appearance resolve subtracts the old direct contribution and replaces it
with the per-source BRDF response. It retains the existing indirect term once.
The same finite-patch emitter packet, inverse-square metric/window, coarse
transmittance and persistent fine visibility are used. No native second emitter
or view-independent shaded-color cache is introduced. Each light keeps its own
color and direction. No specular response is added to the indirect field, whose
existing finite-patch approximation and passive generation budgets are unchanged.
The combined multibounce appearance is not claimed to be a calibrated layered
BSDF or globally exact light transport.

Coarse optical transmittance is interpolated using independent geometric stencil
weights. It must not be inferred from the receiver's base color: a black
substrate can still reflect at a dielectric boundary. Recovery records store
these scalar weights in their previously unused coefficient W values; RGB and
record sizes are preserved. Captured source ownership/normal/depth restrictions
still limit recovery. Unwitnessed or overflow pixels retain the baseline path.

A normal-variance option broadens microfacet width using the length of the
already accumulated source normals. It does not edit captured normals, smooth
base color, fill real openings or alter geometric shadow queries. This is a
spatial footprint approximation, not temporal antialiasing or a full EWA filter.
Recovered holes use their nearest genuine source's roughness and geometric
normal; they do not acquire a fabricated normal variance estimate.

## Controls and validation

The same validated `command()` path owns `material_response`, `bounded_raster`
and `normal_filtering`; invalid mixed transactions fail before scene revision.
The optical response requires the existing `surface_detail` mode. Disabling it
keeps the accepted coarse/direct mode. Existing ID resolution, shared sample
leases and per-light persistent cache continue to work.

* CPU float64 oracle uses explicit Smith lambda/G, independent of the GPU's
  cancellation-free denominator. Tests cover reciprocity, rigid frame rotation,
  zero survival, normal variance, and a 25-point white-furnace numerical grid.
  This finite quadrature audit is not a proof for every possible material.
* Conservative row coverage is checked against exhaustive pixels in 1200
  independent rotated SPD ellipses, including subpixel and capped footprints.
* Actual Vulkan uses the shared BRDF include, not a reimplemented test shader;
  46 direction/roughness/normal/survival cases compare against float64.
* WALL12 compares all-new-controls OFF against WALL11, then bounded vs square
  raster at frontal/oblique/grazing views, requiring equal depth and coverage.
  Further tests cover cached/cold material light, camera changes, independent
  source superposition in linear radiance, dark scenes, constant allocation,
  one collider, genuine source instances and idle reuse.

No area emitters, transmission, metals, native depth/shadow bridge, spatial
light-cache invalidation, dynamic world streaming or full photographic coverage
are introduced by this stage. There is no Godot core fork: these changes fit the
existing RenderingDevice compositor extension point. Physical Android FPS,
thermal behavior and the material's subjective appearance require device testing.
